# Local containers

From the repository root, with a private `.env` generated by `pnpm setup:local`:

```sh
docker compose --env-file .env -f infrastructure/docker/compose.yaml up -d db
docker compose --env-file .env -f infrastructure/docker/compose.yaml ps
```

PostgreSQL/PostGIS uses an isolated named volume and a loopback-only host binding
on port 5433. `down` preserves database data; `down -v` destroys it and must never
be used on a valued environment without an explicit backup/recovery decision.
Changing `POSTGRES_PASSWORD` after volume initialization does not rotate the
existing PostgreSQL role password; perform a controlled database credential change
instead of assuming an environment edit updates persisted roles.

An optional MinIO overlay is available for future S3 integration testing. Set a
unique `MINIO_ROOT_USER` and a generated `MINIO_ROOT_PASSWORD` in private settings,
then run:

```sh
docker compose --env-file .env -f infrastructure/docker/compose.yaml -f infrastructure/docker/compose.storage.yaml --profile storage up -d storage
```

Only the explicit overlay requires MinIO credentials, so starting the core database
does not need unused storage settings. Create a development bucket and scoped
application credentials through the MinIO console. The current production S3
adapter must be implemented and verified before using this service for application
uploads; merely starting it does not wire it into the API.

`api.Dockerfile` is a deployment recipe to build from the repository root. It keeps
the complete workspace for reliable pnpm dependency resolution; a production image
can be reduced after build/runtime verification. Secrets are excluded by
`.dockerignore` and must be injected at runtime. Never pass secret values as Docker
build arguments or commit a populated `.env`.
